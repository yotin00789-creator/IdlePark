# IdlePark · สมุดบัญชีที่จอดรถ

ระบบบัญชีที่จอดรถรายเดือนสำหรับใช้ภายในครอบครัว แทนสมุด Excel รายรับรายคัน (พ.ศ. 2565–2570 และเงินเก็บพ่อ)
คงสูตรเดิมของ Excel ทุกตัว ตัวเลขตรงกับไฟล์เดิม เพิ่มผู้ใช้ด้วยอีเมล มีประวัติการใช้งาน (audit log) แจ้งเตือนผู้ที่ยังไม่จ่าย และกระดิ่งแจ้งเตือนในระบบ

- หน้าเว็บ: Vite + React + Tailwind v4 · three.js (ผังที่จอด 3 มิติ) · ฟอนต์ IBM Plex Sans Thai (ฝังในแอป ไม่โหลดจาก CDN)
- API: Vercel Functions (`api/index.ts` → `server/`) · ฐานข้อมูล PostgreSQL
- อีเมล: Gmail SMTP (nodemailer) · แจ้งเตือนอัตโนมัติ: Vercel Cron

## รันในเครื่อง

```bash
npm install
cp .env.example .env            # ไม่ต้องแก้อะไรก็รันได้ (ใช้ฐานข้อมูลจำลองใน .data/)
npm run seed -- "./ที่จอดรถ (1).xlsx"     # นำเข้าข้อมูลจริงจาก Excel (รันซ้ำได้ ไม่ซ้ำข้อมูล)
npm run dev                     # เปิด http://localhost:5173 แล้วสร้างผู้ดูแลคนแรกที่หน้า /setup
```

`npm run seed` พิมพ์รายงานหลังนำเข้า: จำนวนปี/แถว/ช่องที่มีค่า แถวที่ต้องตรวจ (ไม่ระบุชื่อ) และผลเทียบกับทุกเซลล์สูตรใน Excel (ต้องต่าง = 0)
ใส่ `--force` เพื่อล้างข้อมูลบัญชีแล้วนำเข้าใหม่ (ผู้ใช้ไม่ถูกลบ)

เมื่อลองใช้ระบบจนมีข้อมูลทดสอบปนกับข้อมูลจริง: หยุด `npm run dev` แล้วรัน `npx tsx scripts/reset-real.ts "./ที่จอดรถ (1).xlsx"` ระบบสำรองฐานข้อมูลเดิมไว้ใน `.data/backup-*` แล้วคืนเหลือเฉพาะข้อมูลจาก Excel (เก็บผู้ใช้ ตั้งค่า และโซนที่ตั้งชื่อไว้)

ถ้ายังไม่ตั้งค่า SMTP อีเมลทั้งหมดจะถูกบันทึกเป็นไฟล์ HTML ใน `.data/outbox/` ให้เปิดดูหน้าตาได้

## ตั้งค่า Gmail SMTP

1. บัญชี Google → ความปลอดภัย → เปิด **การยืนยันแบบ 2 ขั้นตอน**
2. สร้าง **รหัสผ่านแอป (App password)** 16 ตัว
3. ตั้งค่า `SMTP_USER` (อีเมล Gmail) และ `SMTP_PASS` (รหัสผ่านแอป) ใน `.env` หรือใน Vercel
4. เข้าเมนู **ผู้ใช้งาน → ส่งอีเมลทดสอบถึงฉัน** เพื่อตรวจ

ข้อควรรู้: Gmail ส่งได้วันละประมาณ 500 ฉบับ เพียงพอสำหรับใช้ในครอบครัว

## Deploy บน Vercel

1. สร้างฐานข้อมูล Postgres: Vercel → Storage / Marketplace → **Neon** (ฟรี) แล้วคัดลอก connection string (แบบ pooled) เป็น `DATABASE_URL`
2. สร้างโปรเจกต์ Vercel จากโฟลเดอร์นี้ (Framework: Vite) แล้วตั้ง Environment Variables:

| ตัวแปร | ค่า |
|---|---|
| `DATABASE_URL` | connection string ของ Postgres |
| `SESSION_SECRET`, `MFA_ENC_KEY` | สุ่มอย่างน้อย 16 ตัวอักษร เช่น `openssl rand -base64 32` (**ห้ามเปลี่ยนหลังใช้งาน** ไม่เช่นนั้น MFA/เลขบัญชีที่เข้ารหัสไว้จะถอดไม่ได้) |
| `APP_URL` | เช่น `https://parking.vercel.app` (ใช้ในลิงก์ในอีเมล) |
| `APP_NAME` | ชื่อที่แสดงในอีเมลและแอป MFA |
| `SMTP_USER`, `SMTP_PASS` | Gmail + รหัสผ่านแอป |
| `CRON_SECRET` | ค่าสุ่ม — Vercel Cron ส่งมาเป็น `Authorization: Bearer …` |

3. Deploy (`npm run build` จะบันเดิล API ไว้ที่ `server-dist/` แล้ว build หน้าเว็บ)
4. นำเข้าข้อมูลจากเครื่องของคุณ (ไฟล์ Excel ไม่ถูกอัปโหลดไปไหน และไม่อยู่ใน repo — `*.xlsx` ถูก ignore ไว้แล้ว):
   ```bash
   DATABASE_URL="postgres://…" MFA_ENC_KEY="ค่าเดียวกับบน Vercel" npm run seed -- "./ที่จอดรถ (1).xlsx"
   ```
5. เปิดเว็บ → หน้า `/setup` สร้างผู้ดูแลคนแรก

**งานอัตโนมัติ (แจ้งเตือนค้างชำระ + สำรองข้อมูล)**: `vercel.json` ตั้ง Cron เรียก `/api/cron/tick` **วันละครั้ง เวลา 08.00 น. (เวลาไทย)** ซึ่งใช้ได้กับแผน Hobby และตรงกับเวลาส่งเริ่มต้น
- ถ้าตั้งเวลาส่งอีเมลเป็นเวลาอื่น ต้องให้ Cron ทำงานถี่ขึ้น: ใช้แผน Pro แล้วแก้ `schedule` เป็นรายชั่วโมง (`0 * * * *`) หรือใช้บริการ Cron ภายนอก (เช่น cron-job.org) เรียก `GET https://โดเมนของคุณ/api/cron/tick` พร้อมหัว `Authorization: Bearer <CRON_SECRET>` ทุกชั่วโมง ระบบดูเองว่าถึงเวลาส่งหรือยัง
- ถ้าไม่ตั้ง `DATABASE_URL` บน Vercel ระบบจะแจ้งข้อผิดพลาดแทนที่จะใช้ฐานข้อมูลชั่วคราว (ข้อมูลจะได้ไม่หายเงียบ ๆ)

## การแจ้งเตือนค้างชำระทำงานอย่างไร

ตั้งได้ที่ **ตั้งค่าและแจ้งเตือน**:

- **วันนัดชำระ**: ตั้งเป็นค่าเริ่มต้นของทุกคัน (เช่น วันที่ 5) และตั้งรายคันได้ในฟอร์มรถ (คันหนึ่งวันที่ 5 อีกคันวันที่ 20) ปุ่ม “ซิงก์ทุกคัน” ในหน้าลูกค้าให้ทุกคันของลูกค้านั้นนัดวันเดียวกัน
- **ส่งเมื่อพ้นวันนัด**: คันที่ยังไม่จ่าย ระบบส่งอีเมลหาผู้ดูแลวันถัดจากวันนัดชำระ ตามเวลาที่ตั้ง (ค่าเริ่มต้น 08.00 น.) ถ้าจ่ายแล้วไม่แจ้งอะไร
- รอเพิ่มอีกกี่วันก่อนแจ้งครั้งแรก (0 = วันถัดจากวันนัด)
- แจ้งซ้ำทุกกี่วัน และกี่ครั้งสูงสุด (หรือต่อเนื่อง **จนกว่าจะมีคนบันทึกการชำระเงิน** — เมื่อบันทึกแล้วหยุดเอง)
- ย้อนหลังกี่เดือน (นับเดือนก่อนหน้าที่ยังค้างด้วย)
- ผู้รับ (ผู้ดูแล หรือ ผู้ดูแล+ผู้แก้ไข) และช่องทาง (อีเมล / กระดิ่ง)

นับว่า “ยังไม่จ่าย” เมื่อยอดของเดือนนั้นว่าง เป็น 0 หรือน้อยกว่าค่าเช่า ยกเว้นแถวที่ “ไม่รวม” เลิกเช่า ก่อนเดือนที่เริ่มเช่า หรือจ่ายล่วงหน้าถึงเดือนนั้นแล้ว
ถ้าส่งอีเมลไม่สำเร็จ กระดิ่งยังแจ้ง และระบบจะลองส่งอีกในรอบถัดไป

## สูตรและตัวเลข

ทุกการคำนวณอยู่ที่ [`shared/calc.ts`](shared/calc.ts) ไฟล์เดียว ใช้ร่วมกันทั้งหน้าเว็บ เซิร์ฟเวอร์ และเทสต์
ค่าเริ่มต้นคือ “ตามไฟล์เดิม” ตรงกับ Excel ทุกเซลล์ (ตรวจด้วยเทสต์ที่อ่านไฟล์ Excel ของคุณตอนรัน ตัวเลขจริงไม่ถูกเก็บใน repo)

หน้า **ตรวจสอบสูตร** แสดงจุดที่สูตรเดิมไม่สม่ำเสมอ (ดึงจากข้อความสูตรในไฟล์โดยตรง) สลับเป็นมาตรฐานได้ทีละจุด

## ทดสอบ

```bash
npm test                       # calc engine เทียบ Excel ทุกเซลล์ · API · auth · MFA · audit · แจ้งเตือน · ส่งออก Excel
npm run typecheck && npm run lint
```

เทสต์ใช้ฐานข้อมูลจำลอง (PGlite) และรันกับ PostgreSQL จริงได้ด้วย:
`DATABASE_URL=postgres://… npx vitest run --no-file-parallelism` (ล้าง schema ของฐานข้อมูลนั้นทุกครั้ง ใช้ฐานข้อมูลทดสอบเท่านั้น)
เทสต์ตัวเลขต้องใช้ไฟล์ Excel (ตั้ง `SEED_XLSX=path` ถ้าไม่ได้อยู่ที่รากโปรเจกต์) ถ้าไม่มีไฟล์จะข้ามชุดนั้น

## ความปลอดภัย

- รหัสผ่าน: scrypt (N=2¹⁵) อย่างน้อย 12 ตัวอักษร · จำกัดลองผิด 5 ครั้ง/15 นาที ต่ออีเมลและ IP
- Session: คุกกี้ httpOnly + Secure + SameSite=Lax เก็บฝั่งเซิร์ฟเวอร์ (แฮช) หมดอายุเมื่อไม่ใช้ 30 นาที / สูงสุด 12 ชั่วโมง เปลี่ยน id หลังเข้าสู่ระบบ
- CSRF: ตรวจ Origin + header `x-csrf` ทุกคำขอที่แก้ข้อมูล
- MFA: TOTP (RFC 6238) secret เข้ารหัส AES-256-GCM ปฏิเสธรหัสซ้ำ รหัสกู้คืน 10 ชุดใช้ได้ครั้งเดียว
- เลขบัญชีธนาคารเข้ารหัส AES-256-GCM · ทุกการแก้ไข/ดูข้อมูลสำคัญอยู่ใน audit log
- ไม่มี telemetry ไม่โหลดสคริปต์/ฟอนต์จาก CDN

## สำรองข้อมูลด้วยอีเมล (Excel)

ตั้งที่ **ตั้งค่าและแจ้งเตือน → สำรองข้อมูลด้วยอีเมล**: เปิด/ปิดได้ เลือกความถี่ (ทุกวัน/สัปดาห์/เดือน) เวลา และผู้รับ (ผู้ใช้ในระบบ หรือกรอกอีเมลภายนอก) ไฟล์ Excel แนบไปกับอีเมล มีสมุดรายรับทุกปี (สูตร SUM จริง) ลูกค้า รถและช่องจอด โซน เงินเก็บพ่อ และการตั้งค่า **ไม่มี**เลขบัญชีเต็ม รหัสผ่าน หรือ MFA มีปุ่ม “สำรองตอนนี้” และ “ดาวน์โหลดไฟล์” ประวัติการสำรองดูได้ในหน้าเดียวกัน

## รายงาน PDF

เมนู **รายงาน PDF**: เลือกช่วง “ตามเดือน” (เดือนไหนถึงเดือนไหน) หรือ “ตามวันที่” (วัน เดือน ปี ถึง วัน เดือน ปี) กด “สร้างรายงาน” จะได้แบบฟอร์มธุรกิจ A4 (สรุปรายเดือน ยอดสะสม รายการค้างชำระ ตารางรายคัน ช่องลงนาม) แล้วกด “บันทึกเป็น PDF” เลือกปลายทาง Save as PDF ในหน้าต่างพิมพ์ (ใช้ฟอนต์ภาษาไทยของระบบ จึงไม่เพี้ยน)

## ฐานข้อมูล

ทุกหน้าอ่าน/เขียนฐานข้อมูลชุดเดียวกัน ดูที่เก็บและจำนวนข้อมูลได้ที่ **ตั้งค่าและแจ้งเตือน → ฐานข้อมูล** ในเครื่องใช้ PGlite เก็บในโฟลเดอร์ `.data/pglite` (ระบบสั่ง checkpoint ทุกนาทีและตอนปิดโปรแกรม) บน Vercel ต้องตั้ง `DATABASE_URL`

## เวลาและวันที่

ทั้งระบบใช้เวลาประเทศไทย (Asia/Bangkok) และแสดงปี พ.ศ. เช่น “วันที่ 1 มกราคม 2569 เวลา 14.00 น.” (ฟังก์ชันอยู่ใน `shared/thai.ts`)

## สำรองข้อมูลระดับฐานข้อมูล

ข้อมูลทั้งหมดอยู่ใน Postgres: `pg_dump "$DATABASE_URL" > backup.sql` (หรือใช้ branch/backup ของ Neon)
เก็บ `MFA_ENC_KEY` ไว้คู่กับไฟล์สำรองเสมอ

## ผังที่จอด 3 มิติ

เมนู "ผังที่จอด 3 มิติ" (`/lot`) แสดงโมเดล Blender ในโฟลเดอร์ `3d-model/` (ไฟล์ที่ใช้อยู่ใน `public/3d/`)

- กำหนดรถลงช่อง: สมุดรายรับ → แก้ไขผู้เช่า → "ตำแหน่งและรถในผัง 3 มิติ" (ช่องจอด ประเภทรถ สี จังหวัดบนป้าย) หรือเปิดหน้า 3 มิติแล้วคลิกช่องว่าง → "เพิ่มรถใหม่ในช่องนี้"
- สีของช่อง: เขียว = ชำระแล้ว, เหลือง = รอชำระ, แดง = ค้างชำระ (คำนวณจากสมุดรายรับเดือนปัจจุบันและวันครบกำหนดในตั้งค่า), เทา = ว่าง
- คลิกรถ: กล้องไปด้านที่เห็นป้ายทะเบียนและไม่ติดกำแพง พร้อมการ์ดรายละเอียดและปุ่มบันทึกรับเงิน กด X หรือ Esc เพื่อกลับมุมเฉียง · ← → เปลี่ยนคัน
- ช่องหนึ่งมีรถที่ยังเช่าอยู่ได้คันเดียวในช่วงเดือนเดียวกัน
- คลังเก็บของ (กล่องสีเทาดำมุมขวาบน, รหัส K01) ให้เช่าได้เหมือนช่องจอด แต่ไม่มีรถ: เลือก "คลังเก็บของ" ที่ช่อง "ช่องจอด" ในฟอร์มผู้เช่า สีที่หลังคาคลังบอกสถานะค่าเช่าเหมือนช่องจอด
- แก้ไขได้จากหน้า 3 มิติโดยตรง: การ์ดของรถมีปุ่ม "แก้ไขรถ" (ช่อง ประเภท สี ทะเบียน จังหวัด ค่าเช่า) และ "ข้อมูลลูกค้า" (ชื่อ เบอร์โทร) บันทึกแล้วผังเปลี่ยนทันที
